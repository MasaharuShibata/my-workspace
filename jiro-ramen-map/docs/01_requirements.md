# 要件定義書

## 1. システム概要

### 1.1 目的

Googleマップ上の情報をもとに、**二郎系ラーメン店**(ラーメン二郎および、それにインスパイアされた系列店)だけを
一覧・地図で確認できるアプリを提供する。口コミ数と評価から算出した「おすすめ順」で店舗を紹介し、
利用者が行きたい店をお気に入り登録できるようにする。

### 1.2 背景

Googleマップには「二郎系」という検索カテゴリが存在しないため、通常のラーメン検索では他ジャンルの店に埋もれてしまう。
また、単純な評価順(★の数)だけでは、口コミ数が少ない店がたまたま高評価なだけで上位に来てしまい、
実態を反映したおすすめにならない。この2点を解決することを主な目的とする。

### 1.3 想定利用者

- 開発者本人(個人利用)
- 想定同時利用人数: 数名程度(個人〜身内向けの小規模運用)

## 2. 機能要件

| # | 機能 | 概要 |
|---|---|---|
| F1 | 店舗の地図表示 | 登録されている二郎系ラーメン店を地図上にマーカーで表示する |
| F2 | 店舗の一覧表示(おすすめ順) | 口コミ数と評価から算出したスコアの高い順に店舗を一覧表示する |
| F3 | 店舗データの同期 | Google Places APIから、各店舗の評価・口コミ数・位置情報を取得して更新する |
| F4 | ログイン | メールアドレス宛のリンク(マジックリンク)によるログイン。パスワードは使用しない |
| F5 | お気に入り登録 | ログイン中のユーザーが、店舗をお気に入りに登録・解除できる |
| F6 | お気に入り一覧表示 | ログイン中のユーザーが、自分がお気に入り登録した店舗の一覧を見られる |
| F7 | 店舗の追加 | ログイン中のユーザーが、店名と住所を入力して新しい店舗を登録できる |

### 2.1 おすすめスコアの要件

- 口コミ数が少ない店舗が、たまたま高評価なだけで上位表示されないようにすること
- 口コミ数が多いほど、その店自体の評価を重視すること
- 口コミ数が少ないほど、全店舗の平均評価に近づけること
- 具体的な計算式は [03_detailed-design.md](./03_detailed-design.md) を参照

### 2.2 対象外(スコープ外)とする機能

以下は本バージョンでは対象外とする。将来的な拡張候補として `README.md` に記載している。

- 店舗情報の重複チェック・自動マージ
- 都道府県・エリアでの絞り込み検索
- 店舗データ同期の自動実行(定期バッチ)
- レビュー投稿機能(自前でのコメント・評価投稿)
- 管理者権限による店舗の承認フロー(現状は「ログインしていれば誰でも追加可能」)

## 3. 非機能要件

### 3.1 コスト

- 個人利用の規模で、原則として**無料**で運用できること
- 唯一課金の可能性があるのはGoogle Maps Platformであり、無料枠を超えないよう
  データ同期はユーザー操作(ボタン押下)によってのみ実行される設計とすること(自動定期実行はしない)
- 各サービスの料金・無料枠の詳細は [04_environment-setup.md](./04_environment-setup.md) を参照

### 3.2 可用性

- 24時間365日の稼働を保証する必要はない(個人利用のため)
- Supabase無料プランの制約により、1週間アクセスが無いとデータベースが自動的に一時停止する場合がある
  (手動で再開可能、データは消えない)

### 3.3 セキュリティ

- ログインにパスワードを使用しない(漏洩・使い回しリスクを避けるため、メールのマジックリンク方式を採用)
- データベースの操作は、Supabaseの行レベルセキュリティ(RLS)により制御する
  - 店舗データの閲覧: 誰でも可能(ログイン不要)
  - 店舗データの追加: ログインユーザーのみ
  - お気に入りの閲覧・追加・削除: 本人のみ
- 管理者権限が必要な操作(Google Places APIとの同期など)は、ブラウザに公開されない
  サーバー専用の鍵(service role key)を使い、サーバー側の処理としてのみ実行する

### 3.4 保守性

- 将来別の人が見ても分かるよう、設計書・READMEを整備すること(本ドキュメント一式がその対応)
- 環境構築に必要な手順・設定値をすべて文書化すること

## 4. 制約条件

- 開発・運用に使うサービスはすべて無料プラン(個人が新規にアカウントを作る前提)で完結させること
- Google Maps Platformのみ、クレジットカード登録(課金アカウント作成)が必須
- 開発はClaude(AIアシスタント)による支援を受けながら、非エンジニアのオーナーが指示を出す形で行う
  - そのため、環境構築や設定変更の手順は、専門用語を避け、画面のどこを操作するかが分かるレベルまで具体的に記載すること

## 5. 用語集

| 用語 | 説明 |
|---|---|
| 二郎系 | 「ラーメン二郎」およびその系列店・インスパイア店の総称。極太麺・厚切りチャーシュー・大量の野菜などが特徴 |
| マジックリンク | パスワードの代わりに、メールに送られてくるリンクをクリックすることでログインする認証方式 |
| RLS(Row Level Security) | データベースの行(レコード)単位でアクセス制御を行う仕組み。Supabase(PostgreSQL)の機能 |
| service role key | Supabaseの管理者権限を持つ鍵。RLSを無視してすべての操作ができるため、サーバー側でのみ使用する |
| おすすめスコア | 口コミ数と評価から算出する、店舗のおすすめ度を表す数値。詳細設計書を参照 |
