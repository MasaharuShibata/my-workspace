# 要件定義書

## 1. システム概要

### 1.1 目的

手元にある食材をいくつか入力するだけで、AIがそれらの食材を活かしたレシピを考案してくれる
レシピ提案アプリを提供する。気に入ったレシピはお気に入りとして保存し、あとから見返せるようにする。

### 1.2 背景

「冷蔵庫にある食材で何が作れるか思いつかない」という悩みを、AIによるレシピ考案で解決することを目的に企画した。
一般的なレシピ検索サイトのようにあらかじめ登録された既存レシピを検索するのではなく、
入力した食材の組み合わせに応じてAIがその場でレシピを生成する点が特徴。

### 1.3 想定利用者

- 開発者本人のみ(個人利用)。複数人での利用は想定しない

## 2. 機能要件

| # | 機能 | 概要 | 区分 |
|---|---|---|---|
| F1 | 食材の入力 | 検索ボックスに食材を複数入力する(カンマ区切りなどで複数指定可能) | MUST |
| F2 | AIによるレシピ考案 | 入力された食材を元に、AIがそれらを活かしたレシピ(料理名・材料・作り方)を1件考案する | MUST |
| F3 | レシピ結果の表示 | AIが考案したレシピの内容を画面上に表示する | MUST |
| F4 | お気に入り登録 | 表示されているレシピを、気に入った場合にお気に入りとして保存する | WANT |
| F5 | お気に入り一覧表示 | 保存済みのお気に入りレシピを一覧で表示する | WANT |
| F6 | お気に入り削除 | 保存済みのお気に入りレシピを削除する | WANT |

### 2.1 対象外(スコープ外)とする機能

- ログイン・ユーザーごとのデータ分離(個人1人での利用に限定するため、意図的に持たない。詳細は3.3節を参照)
- お気に入り登録していない生成結果の履歴保存(その場で表示するのみで、保存しない限り残らない)
- 生成されたレシピの手動編集
- カロリー・栄養素の計算
- 1回の検索で複数のレシピ候補を提示し、その中から選ぶ機能(まずは1件のみ生成する)
- レシピ画像の生成

## 3. 非機能要件

### 3.1 コスト

- Webアプリのホスティング(Vercel)とデータベース(Supabase)は、個人利用の規模であれば
  無料プラン(Vercel Hobby + Supabase Free)で運用できる
- 一方、レシピ考案に使うAI(Claude API)は**従量課金制で、無料枠に頼らない前提**とする
  (個人利用・検索頻度が低い前提であれば、1回あたりのコストは小さいと想定されるが、
  これまでの他プロジェクトのような完全無料運用ではない点に注意。詳細は
  [04_environment-setup.md](./04_environment-setup.md)(基本設計後に作成)に記載する)

### 3.2 可用性

- 24時間365日の稼働を保証する必要はない(個人利用のため)
- Supabase無料プランの制約により、1週間アクセスが無いとデータベースが自動的に一時停止する場合がある
  (手動で再開可能、データは消えない)

### 3.3 セキュリティ

- 本バージョンではログイン機能を持たない(想定利用者が開発者本人のみのため)
  - そのため、**デプロイ後のURLとSupabaseのanonキーを知っていれば誰でもお気に入りを閲覧・登録・削除できる**
    ことを明確な制約として受け入れる
  - 上記を許容できない場合は、Vercelの「Deployment Protection(パスワード保護)」で
    サイト全体にアクセス制限を掛けることを推奨する
  - お気に入りテーブルへの書き込みは、行レベルセキュリティ(RLS)を有効にした上で
    「anonロールに許可」というポリシーにする(将来ログインを追加する拡張性は残す)
- AI(Claude API)の利用に必要なAPIキーは、**ブラウザに一切公開せず、Vercelのサーバー側処理
  (Route Handler / Server Action)からのみ**呼び出す。フロントエンドから直接AI APIを呼ぶことはしない

### 3.4 保守性

- 将来別の人が見ても分かるよう、設計書・READMEを整備すること(本ドキュメント一式がその対応)
- 環境構築に必要な手順・設定値をすべて文書化すること

## 4. 制約条件

- データベース・ホスティングはSupabase・Vercelを使用すること(指定)
- レシピ考案に使うAIはClaude API(Anthropic)を使用する
  - ChatGPT(OpenAI)でも実現可能だが、開発環境との親和性を考慮しClaude APIを採用する
  - 利用には別途AnthropicアカウントとAPIキー(課金設定)が必要になる
- 開発はClaude(AIアシスタント)による支援を受けながら、非エンジニアのオーナーが指示を出す形で行う
  - そのため、環境構築や設定変更の手順は、専門用語を避け、画面のどこを操作するかが分かるレベルまで具体的に記載すること

## 5. 用語集

| 用語 | 説明 |
|---|---|
| Claude API | Anthropic社が提供するAI(Claude)をプログラムから呼び出すための仕組み。本アプリのレシピ考案機能で使用 |
| RLS(Row Level Security) | データベースの行(レコード)単位でアクセス制御を行う仕組み。Supabase(PostgreSQL)の機能 |
| anonキー / anonロール | ログインしていない状態でSupabaseにアクセスする際に使われる、公開しても問題ない前提のキー・権限 |
| Route Handler / Server Action | Next.jsでサーバー側(ブラウザに公開されない場所)で処理を実行する仕組み。APIキーなどの秘密情報を扱う際に使用 |
