# 02. 開発環境を準備する

> この章のゴール: 自分のPCで「コードを書いて、すぐ画面で確認できる」状態を作る。

---

## 2.1 何を用意するのか

| # | 道具 | 役割 | 例えるなら |
|---|---|---|---|
| 1 | **エディタ**(VS Code) | コードを書く | ノートとペン |
| 2 | **ターミナル** | PCに文字で命令する | 台所の作業台 |
| 3 | **Node.js** | JavaScriptをPC上で動かす土台 | コンロ |
| 4 | **npm** | 部品(ライブラリ)を取り寄せる | 通販サイト |
| 5 | **Git / GitHub** | 変更履歴を残す・公開する | セーブデータ |
| 6 | **ブラウザ**(Chrome) | 動作確認する | 試食 |

3〜4は一緒に入ります。この章では1〜5を入れます。

---

## 2.2 エディタ(VS Code)

https://code.visualstudio.com/ からダウンロードしてインストールします。

入れたら、最低限これだけ設定しておくと後が楽です。

1. 日本語表示にする: 拡張機能で `Japanese Language Pack` を検索してインストール
2. 保存時に自動整形: 設定(`Ctrl+,` / `Cmd+,`)で `format on save` を検索してチェックを入れる

💡 「自動整形」は、インデント(字下げ)や改行の位置を勝手に揃えてくれる機能です。
初心者のうちは **見た目が崩れているせいで読めない** ことが本当に多いので、
最初から入れておく価値があります。

---

## 2.3 ターミナル

黒い画面に文字を打つやつです。怖がる必要はありません。
この教材で使うコマンドは、実質10個もありません。

VS Code の中で開けます: メニューの「ターミナル」→「新しいターミナル」。

### 最低限おぼえるコマンド

| コマンド | 意味 |
|---|---|
| `pwd` | 今どのフォルダにいるか表示(Windowsのコマンドプロンプトでは `cd`) |
| `ls` | 中身の一覧(Windowsでは `dir`) |
| `cd フォルダ名` | そのフォルダに移動 |
| `cd ..` | 1つ上のフォルダに戻る |
| `mkdir 名前` | フォルダを作る |

⚠️ **初心者が最も詰まるのは「今どこにいるか分からない」ことです。**
コマンドがうまく動かないときは、9割の確率で **フォルダの位置が違う** だけです。
まず `pwd`(または `ls`)を打って、今いる場所を確認する癖をつけてください。

## 2.4 Node.js と npm

### Node.js とは

JavaScriptは元々「ブラウザの中でしか動かない言語」でした。
それを **ブラウザの外でも動かせるようにしたもの** がNode.jsです。

これがあるおかげで、サーバー側の処理もJavaScript(TypeScript)で書けます。
つまり **1つの言語で画面もサーバーも書ける**。Next.jsを選ぶ理由の1つがこれです。

### インストール

https://nodejs.org/ から **LTS版**(左側の、推奨と書いてあるほう)を入れます。

確認します。

```
ターミナル
node -v
npm -v
```

こんな感じで数字が出ればOKです。

```
v22.11.0
10.9.0
```

⚠️ `command not found` と出たら、インストール後にターミナルを開き直してください。
それでもダメならインストールし直しです。

### npm とは

Node.jsと一緒に入る **部品の取り寄せツール** です。

世の中には、他の人が作って公開してくれた部品(**パッケージ / ライブラリ**)が
何十万個もあります。my-recipe も、自分で書くのは全体のごく一部で、
残りは他人の部品を組み合わせています。

| my-recipeで使う部品 | 何をしてくれるか |
|---|---|
| `next` | Webアプリの骨組み全部 |
| `react` | 画面の組み立て |
| `@supabase/supabase-js` | データベースへの読み書き |
| `@anthropic-ai/sdk` | Claude APIの呼び出し |
| `zod` | データの形のチェック |
| `typescript` | 型のチェック |

これらは `package.json` というファイルに一覧で書かれます。

```
ターミナル
npm install next     # 部品を1つ取り寄せる
npm install          # package.json に書かれた部品を全部取り寄せる
```

取り寄せた部品の実体は `node_modules` というフォルダに入ります。
中身は数万ファイルになりますが、**中を見る必要はまったくありません**。
そしてこれは **Gitで保存しません**(後述)。`package.json` さえあれば
`npm install` でいつでも再現できるからです。

## 2.5 Git と GitHub

### Git とは

**変更履歴を記録する仕組み** です。ゲームのセーブに近いですが、
「いつでも過去のどのセーブ地点にも戻れる」「何を変えたかが全部残る」点が違います。

初心者にとっての本当の価値は、**壊すのが怖くなくなる** ことです。
「変な風にいじってしまった」がいつでも取り消せます。

### GitHub とは

Gitの履歴を **インターネット上に置いておく場所** です。
バックアップであり、他人と共有する場所であり、そして今回は
**Vercelが「ここからコードを取ってきて公開する」参照元** にもなります。

### インストールと初期設定

https://git-scm.com/ からインストール後、最初の一回だけ名前とメールを登録します。

```
ターミナル
git config --global user.name "あなたの名前"
git config --global user.email "あなたのメールアドレス"
```

### この教材で使うGitコマンド

| コマンド | 意味 |
|---|---|
| `git init` | このフォルダの履歴管理を始める |
| `git status` | 今、何が変わっているか確認 |
| `git add .` | 変更を「記録対象」に入れる |
| `git commit -m "メッセージ"` | 記録する(セーブ) |
| `git push` | GitHubに送る |
| `git log --oneline` | 履歴を見る |

流れは常にこの順です。

```
編集する → git add . → git commit -m "何をしたか" → git push
```

💡 コミットメッセージは「何をしたか」を後から読む自分に向けて書きます。
`修正` `update` では意味がありません。`お気に入り削除ボタンを追加` のように書きます。

### .gitignore

「これはGitで記録しないで」というリストです。**特にこの2つは絶対に入れます。**

```
ファイル名: .gitignore

node_modules/
.env.local
```

⚠️ **`.env.local` にはAPIキーが入ります。これをGitHubに上げると、**
**キーが世界に公開されます。** 悪意のあるプログラムがGitHubを常時巡回していて、
公開されたキーは数分で拾われ、使われます(実際に高額請求の事故が起きています)。

Next.jsでプロジェクトを作ると `.gitignore` は自動で用意されますが、
**中身に `.env.local` があるか自分の目で確認してください。**

## 2.6 ブラウザの開発者ツール

Chrome で `F12`(Macは `Cmd+Option+I`)。これがWeb開発者の聴診器です。
最低限、3つのタブを使います。

| タブ | 何が見えるか | いつ使うか |
|---|---|---|
| **Console** | JavaScriptのエラー・`console.log`の出力 | 画面が動かないとき、まずここ |
| **Network** | 飛んだリクエストと返事 | APIが動いているか確認するとき |
| **Elements** | 今表示されているHTML・CSS | 見た目が崩れているとき |

⚠️ 「動かない」と言う前に必ずConsoleを見てください。
初心者の「動きません」の8割は、Consoleに赤字で答えが書いてあります。

## 2.7 動作確認 — 空のNext.jsを起動してみる

道具が揃ったか、実際に確かめます。**練習用の使い捨てフォルダで**やります。

```
ターミナル
cd デスクトップなど、作業したい場所
npx create-next-app@latest hello-test
```

いくつか質問されます。とりあえず全部この通りに答えてください(意味は Step1 で説明します)。

```
Would you like to use TypeScript?          → Yes
Would you like to use ESLint?              → Yes
Would you like to use Tailwind CSS?        → No
Would you like your code inside a `src/`?  → No
Would you like to use App Router?          → Yes
Would you like to use Turbopack?           → No
Would you like to customize the import alias? → No
```

終わったら、中に入って起動します。

```
ターミナル
cd hello-test
npm run dev
```

こう出れば成功です。

```
▲ Next.js 15.x.x
- Local:  http://localhost:3000
✓ Ready in 1.8s
```

ブラウザで `http://localhost:3000` を開いてください。Next.jsの初期画面が出ます。

### localhost:3000 とは

- `localhost` = **このPC自身**
- `:3000` = 3000番の窓口

つまり「自分のPCの中で動いているサーバーの、3000番窓口」です。
インターネットには一切出ていません。**この時点では、他の人からは見えません。**

### 止め方

ターミナルで `Ctrl + C` です。開発中はずっと起動しっぱなしにします。

💡 `npm run dev` を動かしたまま、**別のターミナルタブ**で他のコマンドを打つのが普通です。
一つのターミナルで全部やろうとして、止めて打って起動して…とやると疲れます。

確認できたら `hello-test` フォルダは消して構いません。
