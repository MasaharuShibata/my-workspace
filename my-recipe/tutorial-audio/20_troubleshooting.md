# 音声版 20章 エラーの読み方と、詰まりどころ集

本編のこの章は、詰まったときに引く辞書として作られています。
音声版では、辞書を引く前に知っておくと効く、
エラーへの向き合い方と、代表的な詰まりどころを、頭に入れておくための章として構成しています。

実際に詰まったときは、本編の20章を開いて、症状から引いてください。

## まず、これをやる

エラーが出たら、この順番で確認します。順番が大事です。

1つめ。エラーメッセージを、最後まで読む。英語でも読みます。

2つめ。どこで起きているかを特定する。
ブラウザのコンソールか、ターミナルか、Vercelのログか。

3つめ。直前に自分が何を変えたかを思い出す。

4つめ。1つだけ元に戻して、直るか確かめる。

やってはいけないのは、
心当たりのある場所を、同時に何か所も書き換えることです。
直っても原因が分からず、次に同じ目に遭います。

動いていた時点に戻れるのが、Gitの価値です。
git stash で変更を一時退避したり、
git diff で何を変えたかを表示したりして、活用してください。

## どこを見ればいいのか

これは非常に重要なので、整理します。

use client と書いたクライアントコンポーネントのエラーは、
ブラウザのコンソールに出ます。

サーバーコンポーネントのエラーは、ターミナルに出ます。本番ではVercelのログです。

ルートハンドラーのエラーも、ターミナル。本番ではVercelのログです。

サーバーアクションのエラーも、同じくターミナル、あるいはVercelのログです。

ビルド時のエラーは、npm run build の出力に出ます。

ログが出ない、という悩みの原因のほとんどは、見る場所が違うだけです。

## Next.jsとReactでよく出るエラー

代表的なものを、7つ紹介します。

### useStateがクライアントコンポーネントでしか動かない、というエラー

原因は、useStateを使っているのに、use client が無いこと。
対処は、ファイルの1行目に、use client を追加することです。
import文より上に書きます。

### オブジェクトはReactの子要素として有効ではない、というエラー

原因は、オブジェクトや配列を、そのまま表示しようとしたこと。

レシピのオブジェクトをそのまま波かっこで囲むのではなく、
その中のタイトル、のように、中の項目を指定するか、
配列ならジョインで文字列にしてから表示します。

### リストの各子要素にはユニークなkeyが必要、という警告

原因は、マップで作った要素にキーが無いこと。
対処は、キーを付けることです。
追加や削除があるリストなら、安定したIDを使います。

### undefinedのプロパティは読めません、というエラー

これが最頻出のエラーです。
無いものの中身を読もうとした、という意味です。

対処としては、オプショナルチェーン、
つまりクエスチョンマークとドットを使います。何段でも書けます。

原因として多いのは3つ。
データがまだ読み込まれていない。つまり非同期の途中である場合。
APIが期待した形を返していない場合。
そして、打ち間違い。たとえば、材料の項目名を単数形で書いてしまった場合です。

調べ方は、落ちる直前にコンソール出力を入れて、中身を見ることです。

### ハイドレーションに失敗しました、というエラー

原因は、サーバーで作ったHTMLと、ブラウザで作ったHTMLが食い違ったことです。

よくある犯人は2つ。
new Date や、Math.random を、描画中に使っている場合。
サーバーとブラウザで値が違うからです。
そして、localStorage を描画中に読んでいる場合。
サーバーには存在しないからです。

対処は、時刻や乱数を使う処理を、
useEffectの中か、イベントハンドラの中で行うことです。

### 画面が更新されない、クリックしても何も起きない

原因のほとんどは、stateを直接書き換えていることです。

配列の要素を直接代入してからセットするのではなく、
マップで新しい配列を作ってセットします。
プッシュで要素を足してからセットするのではなく、
スプレッド構文で新しい配列を作ります。

もう1つの原因は、use client を書き忘れていて、
そもそもイベントが動いていない場合です。

### ボタンが勝手に実行される、無限ループする

原因は、onClickに、関数名のあとにかっこを付けて渡していることです。
描画時に即実行されてしまいます。

関数そのものを渡すか、引数を渡したいならアロー関数で包みます。

### ページが再読み込みされて入力が消える

フォームの送信処理で、preventDefault を忘れています。

### searchParamsでエラーになる

Next.jsのバージョン15から、searchParamsはプロミスです。
awaitを付けて取り出します。

Next.jsはバージョンによる違いが大きいので、
検索して見つけた記事の日付を、必ず確認してください。

## TypeScriptのエラー

4つ紹介します。

### XをYに割り当てることはできません

読み方は、Xを入れようとしたが、Yでなければいけない、です。
対処は、型定義を見直すか、値を正しいものにすることです。

### プロパティxxxは型Yyyに存在しません

原因は、打ち間違いか、型定義に足りていないことです。

ここでひとつコツを。
エディタの補完を使ってください。
オブジェクト名にドットを打てば、候補が出ます。
手打ちしなければ、そもそも打ち間違いません。

### オブジェクトはnullの可能性があります

nullかもしれない値を触っています。
if文で存在を確認してから触ります。

### モジュールが見つかりません

パスの誤りか、ファイル名の誤りです。

確認すべきは2つ。
tsconfig.json にパスの設定があるか。
そして、ファイル名の大文字小文字が合っているか。

2つ目は重要です。
Macは大文字小文字を区別しませんが、Linuxは区別します。
なので、ローカルで動いてVercelで落ちる、という原因になります。

## APIと環境変数まわり

4つ紹介します。

### 認証方法を解決できません、あるいは401

原因は、APIキーが読めていないことです。
チェックリストは5つ。

.env.local がプロジェクト直下にあるか。appフォルダの中ではありません。
変数名が完全に一致しているか。
イコールの前後に空白が無いか。
開発サーバーを再起動したか。これが最頻出です。
そして本番なら、Vercelの環境変数に登録したか。

環境変数は、起動時に読み込まれます。編集したら、必ず再起動です。

### クレジット残高が低すぎます

Anthropicアカウントに支払い方法が登録されていないか、残高不足です。
コンソールのビリングを確認します。

### ローカルでは動くのに、本番で動かない

ほぼ100パーセント、環境変数の登録漏れです。

Vercelのプロジェクト設定で、3つ全部あるか確認します。
そして、追加した後は、再デプロイが必要です。

### Supabaseで、新しい行が行レベルセキュリティポリシーに違反します

RLSのポリシーが足りていません。
スキーマのSQLの、ポリシー作成の部分を実行したか確認します。

なお、Supabaseに接続できないときは、
1週間アクセスが無いと無料プランのデータベースが自動で一時停止することを、思い出してください。
ダッシュボードから手動で再開できます。データは消えていません。

## 環境とツールまわり

4つ紹介します。

npm run dev が動かないとき。
pwd で今どこにいるかを確認し、ls で package.json があるかを見ます。
プロジェクトフォルダの中にいない、というのが最頻出の原因です。

npm install が失敗するとき。
node_modules と package-lock.json を削除してから、やり直すと直ることが多いです。
依存関係のキャッシュがおかしくなった場合です。

npm run dev は通るのに、ビルドで落ちるとき。
開発モードは型エラーを警告で済ませますが、ビルドは止めます。
デプロイ前に、必ずビルドを通してください。

ポート3000が使われているとき。
前回の開発サーバーが残っています。
コントロールとCで止めるか、別のポート番号を指定して起動します。

## 見た目の問題

6つ、症状と原因を挙げます。

横スクロールが出る。
ボックスサイジングの指定忘れか、要素が画面幅を超えています。

Flexboxの中身がはみ出す。

ボタンだけフォントが違う。
ボタンのフォントファミリーを継承にします。

CSSが効かない。

CSSが効かない、その2。

スマホで勝手に拡大する。
入力欄のフォントサイズを16ピクセル以上にします。

## エラーの調べ方

4つの手順を紹介します。

### 1つめ エラーメッセージで検索する

このとき、自分のファイル名や変数名は、検索語から外します。
一般的な部分だけで検索するのが、コツです。

### 2つめ 記事の日付を見る

Next.jsは変化が速いので、2年前の記事は別物のことがあります。
App Routerなのか、Pages Routerなのかも、確認してください。
appフォルダを使うのが、App Routerです。

### 3つめ 公式ドキュメントを見る

Next.js、React、TypeScript、Supabase、Anthropic。
それぞれに公式のドキュメントサイトがあります。

最初は読みにくいですが、公式が最も正確で、最も新しいです。
ブログ記事で概要をつかんで、公式で確認する。
この使い分けが効率的です。

### 4つめ 最小の再現を作る

原因が分からないときは、問題が起きる最小のコードを作ります。

関係ない部分を削っていくと、たいてい途中で、
あ、これが原因だった、と自分で気づきます。

これは、デバッグの最も確実な手法です。

## デバッグの心構え

5つ、お伝えします。

エラーメッセージは、あなたを助けようとしています。読んでください。

動かない、で止まらず、どこまで動いているか、を確認してください。

console.logを惜しまないでください。変数の中身を見るのが、最短です。

一度に1つだけ変えてください。

そして、詰まったら休憩してください。
翌朝に一瞬で気づくことは、本当に多いです。

最後にひとつ。
初心者と経験者の差は、知識量よりも、切り分けの速さです。

エラーを恐れず、1つずつ潰す習慣が、そのまま実力になります。
