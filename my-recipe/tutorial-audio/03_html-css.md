# 音声版 3章 HTMLとCSS 画面はどうやってできているか

この章のゴールは、HTMLで構造を作り、CSSで見た目を作る、
という役割分担を理解することです。
そして、マイレシピの画面がどのタグでできているかを読めるようになることです。

この章からコードの話が始まります。
音声版では、コードそのものは読み上げず、
そのコードが何をしているのかを言葉で説明していきます。

## HTMLは文書の構造を書くもの

まず大前提として、HTMLはプログラミング言語ではありません。
文書に、意味の札を貼る仕組みです。

たとえば、マイレシピという文字を、エイチワンという札で囲むと、
これは大見出しです、という意味になります。
手元にある食材を入力するとAIがレシピを考案します、という説明文を、
ピーという札で囲むと、これは段落です、という意味になります。

この囲むものを、タグと呼びます。
開始タグと終了タグがペアになっていて、終了タグのほうにはスラッシュが付きます。
そして、タグで囲まれたひとまとまりのことを、要素、英語でエレメントと呼びます。

要素の中には、さらに要素を入れられます。これを入れ子、あるいはネストと呼びます。
これがHTMLの構造です。

たとえば、アーティクルというタグで大きな箱を作って、
その中に、エイチスリーの見出しでレシピ名を入れ、
その下にピーの段落で調理時間を入れる。こういう形です。

ここで注意がひとつ。入れ子の順番を、交差させてはいけません。
ピーの中にストロングを入れたなら、閉じるときは内側のストロングから先に閉じて、
そのあとピーを閉じます。
外側から先に閉じてしまうのは、間違いです。

それから、属性という仕組みがあります。
これはタグに追加情報を持たせるもので、名前イコール、ダブルクォートで囲んだ値、という形で、
開始タグの中に書きます。

たとえば、リンクを作るAタグには、hrefという属性で、リンク先を指定します。
入力欄を作るインプットタグには、typeという属性で入力の種類を、
プレースホルダーという属性で、薄く表示される例文を指定します。
画像を出すイメージタグには、srcで画像の場所を、altで画像の説明を指定します。

## マイレシピで実際に使うタグ

覚えるべきタグは、実は10個ちょっとです。順に挙げます。

エイチワンからエイチフォー。見出しです。数字が小さいほど上位になります。
ページタイトルや、材料、作り方、といった小見出しに使います。

ピー。段落です。説明文やエラーメッセージに使います。

ユーエルとエルアイ。順序なしリストです。材料リストに使います。

オーエルとエルアイ。順序ありリストです。自動で番号が付きます。作り方の手順に使います。

フォーム。入力のまとまりです。食材入力フォームに使います。

インプット。1行入力欄や、チェックボックスです。食材の入力や、材料のチェックに使います。

セレクトとオプション。選択肢です。ジャンル選択に使います。

ボタン。そのままボタンです。レシピを考えてもらう、のボタンですね。

ラベル。入力欄の説明ラベルです。食材、カンマ区切り、といった説明に使います。

エー。リンクです。ヘッダーのナビゲーションに使います。

ディブ。意味を持たない箱です。レイアウト調整用に使います。

スパン。これも意味を持たない箱ですが、文の中で使うものです。バッジなどの装飾に使います。

そして、ヘッダー、メイン、セクション、アーティクル。これらは意味のある箱です。
構造の整理に使います。

ここで、ディブとセクションの違いを説明します。
見た目は、どちらも同じ、ただの箱です。違うのは、意味があるかどうかです。

ディブは、ただの箱。見た目を整えるためだけのものです。
セクション、アーティクル、ヘッダーは、
ここは記事です、ここはヘッダーです、という意味を持っています。

意味のあるタグを使うことを、セマンティックHTMLと言います。
こうしておくと、検索エンジンや、
目の見えない人が使う読み上げソフトが、内容を理解しやすくなります。

マイレシピでは、レシピ結果を表示する部品がセクションを使い、
お気に入りカードの部品がアーティクルを使っています。この考え方によるものです。

ただし、迷ったらディブで構いません。慣れてから直せばいい話です。

リストの使い分けについても触れておきます。
ユーエルは、先頭に中黒、つまり点が付きます。
オーエルは、1、2、3という番号が自動で付きます。
手順は番号に意味があるのでオーエル、
材料は順不同なのでユーエル、という使い分けです。

フォームについて、ひとつ地味だけれど効くテクニックがあります。
ラベルタグのfor属性と、インプットタグのid属性を、同じ名前で揃えることです。
こうすると、ラベルの文字をクリックしたときに、入力欄にカーソルが入ります。
スマホでは特に押しやすくなります。

チェックボックスは、インプットタグのtype属性を、チェックボックスに変えるだけで作れます。
インプットは、typeを変えるだけで姿が変わります。
テキスト、チェックボックス、ナンバー、デートなどがあります。

## CSSは見た目を書くもの

HTMLが、何であるか、を書くものだとすれば、
CSSは、どう見えるか、を書くものです。

CSSの書式は、3つの部分でできています。

1つめがセレクタ。どの要素に適用するか、です。
2つめがプロパティ。何を変えるか、です。
3つめが値。どう変えるか、です。

たとえば、エイチワンというセレクタに対して、
フォントサイズというプロパティに32ピクセルという値、
カラーというプロパティに濃い茶色を指定する。こういう形です。

セレクタの種類は、5つ知っていれば十分です。

タグの名前をそのまま書くと、そのタグ全部に適用されます。
ドットのあとに名前を書くと、その名前のクラスが付いた要素に適用されます。
シャープのあとに名前を書くと、そのidが付いた要素に適用されます。
セレクタをスペースでつないで2つ書くと、前者の中にある後者、という意味になります。
セレクタのあとにコロン、ホバーと書くと、マウスが乗っているとき、という意味になります。

実務では、ほぼクラスのセレクタだけを使います。
マイレシピのスタイルシートを見ても、
レシピ・リザルト、フェイバリット・カードのように、クラス指定ばかりです。

HTML側で、アーティクルタグにクラス名を付けておいて、
CSS側で、そのクラス名に対して、背景色は白、角丸は14ピクセル、内側の余白は16ピクセル、
といった指定をする。これが基本の流れです。

よく使うプロパティを挙げます。

カラーは文字色。
バックグラウンドは背景。
フォントサイズは文字の大きさ、フォントウェイトは文字の太さ。
パディングは、枠の内側の余白。
マージンは、枠の外側の余白。
ボーダーは枠線。
ボーダーレイディアスは角丸。
ディスプレイは並べ方。これは後で詳しくやります。
そしてギャップは、要素同士の間隔です。

## パディングとマージンの違い

これは超頻出なので、丁寧に説明します。

箱を、外側から順番に見ていきます。
いちばん外側にあるのがマージンです。これは箱と箱の間の距離です。
その内側に、ボーダー、つまり枠線があります。
さらにその内側にあるのがパディング。これは箱の中の余白です。
そして、いちばん内側に中身があります。

重要な違いは、背景色が付く範囲です。
パディングは、背景色が付く範囲に含まれます。
マージンには、背景色は付きません。

使い分けの目安はシンプルです。
文字と枠線が近すぎる、と感じたら、パディングを増やします。
カード同士がくっついている、と感じたら、マージン、
あるいは親要素のギャップを増やします。

色の書き方も触れておきます。
よく使うのは、シャープのあとに6桁の16進数を書く形です。
最初の2桁が赤、次の2桁が緑、最後の2桁が青の強さを表しています。
ほかに、赤緑青をそれぞれ0から255の数字で書くRGB形式、
そこに透明度を足したRGBA形式があります。
自分で計算する必要はありません。カラーピッカーで選んで貼るだけです。

## レイアウト Flexbox

横に並べたい、という要望の答えは、ほぼFlexbox、フレックスボックスです。

やることはシンプルで、
並べたい要素たちの親に対して、ディスプレイというプロパティにフレックスという値を指定する。
それだけで、中身が横一列に並びます。
あわせてギャップを指定すれば、要素同士の間隔も調整できます。

マイレシピの食材入力の行も、これだけで、
インプットとセレクトとボタンが横に並んでいます。

よく使う追加の指定を挙げます。

ジャスティファイ・コンテントに、スペース・ビトウィーンを指定すると、
両端に寄せて、間を空けてくれます。
ヘッダーの、左にロゴ、右にナビゲーション、という配置はこれです。

アライン・アイテムズに、センターを指定すると、縦方向の中央揃えになります。

フレックス・ディレクションに、カラムを指定すると、横ではなく縦に並びます。

フレックス・ラップに、ラップを指定すると、はみ出したときに折り返します。

フレックスに1を指定すると、余った幅を、その要素に吸わせることができます。

マイレシピのヘッダーは、実質、ディスプレイのフレックスと、
スペース・ビトウィーンと、センター揃え、この3つだけでできています。

補足です。昔は、フロートという難解な方法を使っていました。
今はもう忘れて大丈夫です。
横並びはFlexbox、格子状に並べたいときはGrid、グリッド。
この2つだけ覚えれば、まず困りません。

## CSS変数

同じ色をあちこちに書いてしまうと、あとで変更するとき、全部を直すことになります。
そこで、色に名前を付けて、一箇所で管理します。これをCSS変数、
あるいはカスタムプロパティと呼びます。

書き方は、コロン、ルート、という特別なセレクタの中に、
ハイフン2つで始まる名前で、値を定義します。
たとえば、カラー・アクセントという名前にオレンジ、
カラー・テキストという名前に濃い茶色、
レイディアス・エムディーという名前に14ピクセル、といった具合です。

使うときは、varと書いて、かっこの中に、そのハイフン2つの名前を入れます。

コロン、ルートというのは、ページ全体を指す特別なセレクタです。

マイレシピのグローバルCSSというファイルは、冒頭でこの定義をまとめています。
つまり、アプリの配色を変えたければ、
この十数行を書き換えるだけで、全体の見た目が変わるということです。
これは、デザインの統一という設計判断によるものです。

## スマホ対応 レスポンシブ

画面の幅によって、CSSを切り替える仕組みがあります。

たとえば、通常のパソコンの画面では、食材入力の行を横並びにしておいて、
画面幅が600ピクセル以下のときだけ、縦並びに切り替える。こういうことができます。

この切り替えを書く仕組みを、アットマーク・メディア、と書くので、
メディアクエリと呼びます。
かっこの中に、マックス・ウィズ、600ピクセル、のように条件を書いて、
その中に、条件を満たしたときだけ適用するCSSを書きます。

マイレシピはスマホで使うことを想定しているので、この切り替えが要ります。

## この章のまとめ

HTMLは構造、CSSは見た目。この役割を混ぜないことが大事です。

タグは10個ちょっと覚えれば、このアプリは作れます。

リストは、順不同ならユーエル、順番に意味があるならオーエルを使い分けます。

CSSは、クラスセレクタがほぼ全てです。

パディングは内側、マージンは外側。

横並びはFlexbox、色やサイズはCSS変数で一元管理。

スマホ対応はメディアクエリ。

## やってみよう

手を動かせる環境があるときに、試してほしいことがあります。

テキストエディタで、test.html というファイルを作って、
カードのクラスを持つ箱の中に、レシピ名の見出しと、材料のリストを書いてください。
そして、スタイルタグの中に、そのカードのクラスに対するCSSを書きます。
背景は白、パディングは16ピクセル、角丸は14ピクセル、あたりから始めるとよいです。

書けたら、そのファイルをブラウザで開いてみてください。
そしてCSSの値を自由に変えて、見た目がどう変わるかを体験してください。

具体的なコードは、本編の3章の最後に載っています。

次の章は、JavaScriptです。
