# 音声版 17章 ステップ9 CSSで仕上げる

この章のゴールは、機能が全部動いている状態のアプリに、見た目を与えることです。
そして、なんとなくAIが作った風、を避ける、デザインの考え方も扱います。

## なぜ最後にやるのか

CSSを最初に凝ると、機能追加のたびにHTMLの構造が変わり、書いたCSSが無駄になります。

いま、構造は確定しています。だから、安心して装飾できます。

ただし、読める程度のCSSは、途中でも書いてきました。
真っ白な画面で開発を続けるのも、それはそれで辛いからです。バランスの問題です。

## デザインを決める前に考えること

初心者がやりがちなのは、思いついた色を、その場で足していくことです。
結果として、こうなります。

微妙に違うグレーが7種類。
角丸が、8ピクセル、10ピクセル、12ピクセル、14ピクセル、とバラバラ。
余白が、13ピクセル、15ピクセル、18ピクセル、と、意味なく違う。

まとまりが無く、テンプレートっぽい、素人っぽい印象になります。

対策は1つです。先にルールを決め、それだけを使うこと。
このルールの集まりを、デザイントークンと呼びます。

### 色を決める

マイレシピのテーマは、料理、家庭的、あたたかい、です。そこで、

ベースは、生成り色。白ではなく、わずかに黄みのある背景です。
アクセントは、オレンジ系。食欲と温かみです。
文字は、黒ではなく、こげ茶寄りにします。

ここが大事です。
真っ黒と、真っ白を、背景と文字に使わない。
これが、洗練して見せるコツです。

コントラストが強すぎて目が疲れますし、
どこかのテンプレートそのままに見えてしまいます。

用途ごとに決めた色は、10色です。

背景は、生成り。
カードの面は、白。
入力欄などの代替の面は、少し濃い生成り。
境界線は、薄いベージュ。
文字は、こげ茶に近い黒。
補助的な文字は、グレージュ。
アクセントは、オレンジ。
ホバー時のアクセントは、濃いオレンジ。
フォーカスリング用の淡いアクセント。
そして、削除やエラー用の、危険を表す赤。

色数は、10個前後に抑えます。多いほど、素人っぽくなります。

### サイズの段階を決める

余白、角丸、文字サイズは、決まった段階だけを使います。

余白は、4、8、12、16、22、28、40ピクセル。
角丸は、中が14ピクセル、大が20ピクセル、カプセル型が999ピクセル。
影は、弱と中の2種類だけ。

この、段階の考え方を、スケールと呼びます。
これを守るだけで、見た目の完成度が、明確に上がります。

### トークンとしてCSSに書く

グローバルCSSの先頭で、コロン・ルートのセレクタの中に、
これらを全部、CSS変数として定義します。

そして以降は、色を直接書かず、必ずvarで変数を参照します。

こうすると、配色を変えたくなったとき、
この十数行だけを書き換えれば、全体が変わります。

## 土台を整える

土台のCSSで、地味だけれど効く指定が4つあります。

1つめ。行の高さ、line-heightを1.65にすること。
日本語は、1.6から1.8が読みやすいです。
ブラウザの既定値である1.2は、詰まりすぎです。

2つめ。フォントスムージングを、アンチエイリアスにすること。
Macで、文字が細く滑らかになります。

3つめ。ボタンのフォントファミリーを、inherit、つまり継承にすること。
これは、ボタンだけ別のフォントになる問題を防ぎます。
ブラウザの既定を上書きしているわけです。

4つめ。見出しの文字間隔を、わずかにマイナスにすること。
少し詰めることで、引き締まります。

3番目は、特に忘れがちです。
指定しないと、ボタンの中だけ明朝体やシステムフォントになり、
理由の分からない違和感の原因になります。

## ヘッダー

ヘッダーには、3つのテクニックを使っています。

### position sticky

ポジションをstickyにして、topをゼロにすると、
スクロールしてもヘッダーが上に貼り付きます。

あわせて、z-indexを指定します。これは重なり順で、大きいほど手前です。

### 半透明とぼかし

背景色を、透明度0.82のRGBA形式で指定し、
さらに、バックドロップ・フィルターで、12ピクセルのぼかしをかけます。

背景が透けつつ、後ろがぼやけます。
スクロールしたときに、下のコンテンツが薄く透けて、上品に見えます。

### 疑似要素で装飾を足す

ブランド名のセレクタに、コロン2つ、before、と書くと、
その要素の前に、CSSだけで要素を作れます。

ここでは、10ピクセル四方の、角丸50パーセント、つまり円を作り、
オレンジで塗って、その周りに淡いオレンジの輪を描いています。

輪を描くには、ボックスシャドウで、
横ずれゼロ、縦ずれゼロ、ぼかしゼロ、広がり4ピクセル、と指定します。
ぼかしをゼロにするのが、輪を描くテクニックです。

HTMLを汚さずに、CSSだけで小さな丸を追加しているわけです。

こういう、小さなアクセントが1つあるだけで、
ちゃんとデザインされている、という印象になります。
ロゴが無くても、ブランドらしさが出ます。

## ボタン

ボタンの質感は、アプリ全体の印象を大きく左右します。

主役のボタンには、
オレンジの背景、白い文字、枠線なし、
たっぷりのパディング、カプセル型の角丸、やや太いフォント。
そして、トランジションを指定します。

### transition

背景色の変化に、0.15秒のトランジションを指定します。
色が、0.15秒かけて滑らかに変わります。
無いと、ぱっと切り替わって、安っぽく見えます。

目安は、0.15秒から0.2秒です。
0.5秒にすると、もっさりします。

### ホバーの指定

ホバーのセレクタに、コロン、not、かっこ、コロン、disabled、と続けます。
マウスが乗っていて、かつ無効化されていないとき、という意味です。

無効なボタンが色を変えると、押せそうに見えて、紛らわしいからです。

### disabledの見せ方

不透明度を0.55にして薄くし、
カーソルを、ノット・アラウド、つまり禁止マークにします。

押せないことが、一目で分かるのが大事です。

### セカンダリボタン

別のレシピを提案してもらう、というボタンは、主役ではありません。
なので、背景を透明にして、枠線だけにします。

ボタンの見た目に序列を付けるのは、UIの基本です。
同じ見た目のボタンが並ぶと、利用者はどちらを押すべきか、迷います。

## 入力欄とフォーカス

入力欄には、3つの注意点があります。

### outline none の重大な注意

フォーカス時のスタイルで、
アウトラインをnoneにして、既定の枠線を消しています。

ただし、必ず代わりの表示を付けます。
ここでは、ボーダーの色をオレンジに変え、
さらに、ボックスシャドウで淡いオレンジの輪を描いています。

アウトラインをnoneにするだけで、代わりを用意しないのは、やってはいけません。

キーボードだけで操作している人にとって、
フォーカスの枠線は、いま自分がどこにいるかを知る、唯一の手がかりです。
それを消すと、アプリが使えなくなります。

消すなら、必ず別の形で示す。これは守るべきルールです。

### min-width ゼロ

Flexboxの中の要素は、既定では、中身より小さくなりません。
だから、長い文字を入れると、はみ出します。

最小幅をゼロに指定すると、縮むようになります。

Flexboxの中身がはみ出す、という問題の9割は、これで直ります。
覚えておく価値があります。

### 単位の話

フォントサイズの単位には、3種類あります。

ピクセルは、絶対値。
rem、レムは、ルート、つまりhtml要素の文字サイズの倍数。
em、エムは、親要素の文字サイズの倍数。

remを使うと、利用者がブラウザの文字サイズ設定を変えたとき、
それに追従して拡大されます。
本文のサイズは、remが無難です。

そしてもうひとつ、スマホ特有の注意です。
フォントサイズが16ピクセル未満の入力欄にフォーカスすると、
iOSが勝手に画面を拡大します。

入力欄だけは、16ピクセル、つまり1rem以上にすると、防げます。

## カードと影

カードには、白い背景、枠線、大きめの角丸、たっぷりのパディング、そして影を付けます。

### 影の付け方

ボックスシャドウの値は、
横ずれ、縦ずれ、ぼかし、そして色、という順で読みます。

ここでコツが2つあります。

1つめ。影を、真っ黒にしないこと。
背景の色味、ここでは茶系を混ぜた色にすると、浮いて見えません。

2つめ。透明度は、0.05から0.1程度で十分です。
濃い影は、古くさく、素人っぽく見えます。

## スマホ対応

メディアクエリで、画面幅640ピクセル以下のときの指定を書きます。

ページのパディングを狭くし、
フォームの行を縦並びにし、
ボタンとセレクトの幅を100パーセントにし、
ヘッダーのパディングと間隔も狭くします。

確認方法は、F12を押して、左上のスマホのアイコン、
トグル・デバイス・ツールバーを押すことです。
実際のスマホ幅で確認できます。

確認すべきことは4つです。

1つめ、横スクロールが出ないこと。これが最重要です。
2つめ、ボタンが押せる大きさであること。目安は44ピクセル四方以上です。
3つめ、文字が小さすぎないこと。本文は14ピクセル以上。
4つめ、入力欄が16ピクセル以上であること。勝手なズームの防止です。

横スクロールは、絶対に潰してください。使い勝手が一気に悪くなります。

原因は、たいてい2つです。
幅を100パーセントにした要素に、パディングが足されている。
つまり、ボックスサイジングの指定忘れです。
あるいは、長い文字列が折り返されていない場合です。

## AIが作った風を避けるために

これは、プロジェクトのルールにも書かれている観点です。
意識的に避けるポイントを、7つ挙げます。

紫から青のグラデーション。
これは避けて、単色にします。題材に合った色を選びます。

真っ黒な文字と、真っ白な背景。
わずかに色味を含ませます。

絵文字を大量に散らすこと。
使わないか、1か所だけにします。

すべてのカードに強い影を付けること。
影は弱く、必要なところだけにします。

角丸がバラバラなこと。
2種類か3種類に統一します。

中央揃えを多用すること。
本文は左揃えにします。日本語は特に、中央揃えだと読みにくくなります。

そして、何々しましょう、という調子の文言。
淡々と、必要なことだけを書きます。

マイレシピの文言を、聞いてみてください。

手元にある食材を入力すると、AIがそれらを活かしたレシピを考案します。
保存したレシピの一覧です。タイトルを押すと詳細が開きます。

説明的で、余計な装飾がありません。これでいいのです。

デザインで迷ったら、引くほうを選んでください。
足した装飾より、揃った余白のほうが、完成度に効きます。

## 最終確認

npm run build、を実行します。
本番と同じ形で固められるかを、確認します。
ここでエラーが出ると、デプロイも失敗します。

よく出るエラーは3つです。

型エラー。TypeScriptの型エラーです。
開発中は警告でも、ビルドでは止まります。

useStateはクライアントコンポーネントでしか動きません、というエラー。
use client の書き忘れです。

ダイナミック・サーバー・ユーセージ、というエラー。
force-dynamic の書き忘れです。

ここは重要です。
npm run dev で動いていても、npm run build で落ちることがあります。
デプロイ前に、必ず一度は実行してください。

成功すると、ルートの一覧が表示されます。
白丸の記号が静的なページ、
イタリック体のfのような記号が、毎回サーバーで動くページです。

お気に入りページが、毎回サーバーで動く側になっていれば、
force-dynamic が効いています。
