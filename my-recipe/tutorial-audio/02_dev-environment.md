# 音声版 2章 開発環境を準備する

この章のゴールは、自分のパソコンで、コードを書いてすぐ画面で確認できる状態を作ることです。

この章は実際にインストール作業をする章なので、聴くだけでは完結しません。
ここでは「何を、なぜ入れるのか」を理解してください。
実際の手順は、本編のテキストを開きながら進めてください。

## 何を用意するのか

用意する道具は6つです。台所に例えながら並べます。

1つめ、エディタ。具体的にはVS Code、ブイエス・コードです。コードを書く道具で、ノートとペンにあたります。

2つめ、ターミナル。パソコンに文字で命令する画面です。台所でいう作業台です。

3つめ、Node.js、ノードジェイエス。JavaScriptをパソコン上で動かす土台です。コンロにあたります。

4つめ、npm、エヌピーエム。部品、つまりライブラリを取り寄せるツールです。通販サイトだと思ってください。

5つめ、GitとGitHub。変更履歴を残して、公開する仕組みです。ゲームのセーブデータにあたります。

6つめ、ブラウザ。Chromeを想定しています。動作確認に使います。試食ですね。

このうち3つめと4つめは、一緒にインストールされます。
この章では1つめから5つめまでを入れます。

## エディタ VS Code

公式サイトからダウンロードしてインストールします。

入れたら、最低限2つだけ設定しておくと、後が楽になります。

1つめは、日本語表示にすること。
拡張機能の画面で、ジャパニーズ・ランゲージ・パックというものを検索してインストールします。

2つめは、保存時の自動整形を有効にすること。
設定画面で、フォーマット・オン・セーブ、という項目を検索してチェックを入れます。

自動整形というのは、インデント、つまり字下げや、改行の位置を、
勝手に揃えてくれる機能です。
初心者のうちは、見た目が崩れているせいでコードが読めない、ということが本当に多いです。
最初から入れておく価値があります。

## ターミナル

黒い画面に文字を打つ、あれです。怖がる必要はありません。
この教材で使うコマンドは、実質10個もありません。

VS Codeの中から開けます。メニューのターミナルから、新しいターミナル、を選びます。

最低限おぼえるコマンドは5つです。

1つめ、pwd。今どのフォルダにいるかを表示します。
Windowsのコマンドプロンプトの場合は、cdだけを打つと同じことができます。

2つめ、ls。今いるフォルダの中身を一覧表示します。Windowsではdirです。

3つめ、cdのあとにフォルダ名。そのフォルダに移動します。

4つめ、cdのあとにドットを2つ。1つ上のフォルダに戻ります。

5つめ、mkdirのあとに名前。フォルダを作ります。

ここで大事な警告です。
初心者が最も詰まるのは、今どこにいるか分からない、ということです。
コマンドがうまく動かないときは、9割の確率で、単にフォルダの位置が違うだけです。
まずpwdを打って、今いる場所を確認する癖をつけてください。

## Node.js と npm

まずNode.jsとは何か。

JavaScriptは、もともとブラウザの中でしか動かない言語でした。
それを、ブラウザの外でも動かせるようにしたものがNode.jsです。

これがあるおかげで、サーバー側の処理もJavaScript、あるいはTypeScriptで書けます。
つまり、1つの言語で画面もサーバーも書ける。
Next.jsを選ぶ理由のひとつが、これです。

インストールは、Node.jsの公式サイトから、LTS版を入れます。
エルティーエス、長期サポート版という意味です。
サイトを開くと左側に、推奨と書いてあるほうがあります。それです。

入ったかどうかの確認は、ターミナルで、nodeスペースハイフンv、と打ちます。
同じようにnpmスペースハイフンv、とも打ちます。
バージョン番号が表示されれば成功です。

もしコマンド・ノット・ファウンド、というメッセージが出たら、
まずターミナルを閉じて開き直してください。
それでもダメなら、インストールをやり直しです。

次にnpmとは何か。
Node.jsと一緒に入ってくる、部品の取り寄せツールです。

世の中には、他の人が作って公開してくれた部品が何十万個もあります。
これをパッケージ、あるいはライブラリと呼びます。
マイレシピも、自分で書くのは全体のごく一部で、残りは他人の部品を組み合わせています。

マイレシピで使う主な部品を挙げます。

next、これはWebアプリの骨組み全部です。
react、これは画面の組み立てです。
supabase-js、これはデータベースへの読み書きです。
anthropic のSDK、これはClaude APIの呼び出しです。
zod、ゾッドと読みます。これはデータの形のチェックです。
そしてtypescript、これは型のチェックです。

これらは、package.json、パッケージ・ドット・ジェイソンというファイルに一覧で書かれます。

部品を1つ取り寄せるときは、npm install のあとに部品の名前を打ちます。
package.jsonに書かれた部品を全部まとめて取り寄せるときは、npm install とだけ打ちます。

取り寄せた部品の実体は、node_modules、ノード・アンダーバー・モジュールズ
というフォルダに入ります。
中身は数万ファイルになりますが、中を見る必要はまったくありません。
そしてこれは、Gitでは保存しません。この理由は、このあとすぐ説明します。
package.jsonさえあれば、npm install でいつでも再現できるからです。

## Git と GitHub

Gitとは、変更履歴を記録する仕組みです。
ゲームのセーブに近いのですが、
いつでも過去のどのセーブ地点にも戻れること、
そして何を変えたかが全部残ること、この2点が違います。

初心者にとっての本当の価値は、壊すのが怖くなくなることです。
変な風にいじってしまった、という状態を、いつでも取り消せます。

GitHubとは、Gitの履歴をインターネット上に置いておく場所です。
バックアップであり、他人と共有する場所であり、
そして今回は、Vercelが「ここからコードを取ってきて公開する」ための参照元にもなります。

インストールしたら、最初の一回だけ、名前とメールアドレスを登録します。
git config のあとに、グローバルという指定と、ユーザー名を渡す形です。
メールアドレスも同じように登録します。

この教材で使うGitのコマンドは6つです。

git init。このフォルダの履歴管理を始めます。
git status。今、何が変わっているかを確認します。
git add ドット。変更を記録対象に入れます。
git commit ハイフンm のあとにメッセージ。これが記録、つまりセーブです。
git push。GitHubに送ります。
git log。履歴を見ます。

流れは、常にこの順です。
編集する、git add する、git commit する、git push する。この繰り返しです。

コミットメッセージについてひとつ。
これは「何をしたか」を、後から読む自分に向けて書きます。
修正、とか、アップデート、では意味がありません。
お気に入り削除ボタンを追加、のように具体的に書いてください。

そして、gitignore、ギットイグノアというファイルの話です。
これは、これはGitで記録しないで、というリストです。
特にこの2つは、絶対に入れます。
ひとつはnode_modulesフォルダ。もうひとつは、.env.local というファイルです。
ドット、イーエヌブイ、ドット、ローカル、と読みます。

ここは、この章でいちばん重要な警告です。
.env.local にはAPIキーが入ります。これをGitHubに上げると、キーが世界に公開されます。
悪意のあるプログラムがGitHubを常時巡回していて、
公開されたキーは数分で拾われ、使われます。
実際に、高額請求の事故が起きています。

Next.jsでプロジェクトを作ると、gitignoreは自動で用意されます。
ですが、中身に .env.local が書かれているかどうかは、必ず自分の目で確認してください。

## ブラウザの開発者ツール

Chromeで、F12キーを押します。Macの場合はコマンドとオプションとIです。
これが、Web開発者の聴診器です。
最低限、3つのタブを使います。

1つめ、コンソール。JavaScriptのエラーや、console.logの出力が見えます。
画面が動かないとき、まずここを見ます。

2つめ、ネットワーク。飛んだリクエストと、その返事が見えます。
APIが動いているかを確認するときに使います。

3つめ、エレメンツ。今表示されているHTMLとCSSが見えます。
見た目が崩れているときに使います。

警告です。動かない、と言う前に、必ずコンソールを見てください。
初心者の「動きません」の8割は、コンソールに赤い字で答えが書いてあります。

## 動作確認 空のNext.jsを起動してみる

道具が揃ったかどうかを、実際に確かめます。
このとき、本番のプロジェクトではなく、練習用の使い捨てフォルダで試します。

やることは、作業したい場所に移動して、
npx create-next-app、という命令で、テスト用のアプリを作ることです。

実行すると、いくつか質問されます。
TypeScriptを使うか、これはイエス。
ESLint、イーエスリントを使うか、これもイエス。
Tailwind CSS、テイルウィンドCSSを使うか、これはノー。
コードをsrcフォルダの中に置くか、これもノー。
App Routerを使うか、これはイエス。
Turbopackを使うか、これはノー。
インポートのエイリアスをカスタマイズするか、これもノー。

それぞれの意味は、9章のステップ1で説明します。今は、この通りに答えてください。

終わったら、作られたフォルダの中に入って、npm run dev、と打ちます。
Next.jsのバージョンと、ローカルホストのコロン3000というアドレス、
そしてレディ、という表示が出れば成功です。

ブラウザで、そのローカルホストのアドレスを開いてください。
Next.jsの初期画面が表示されます。

ここで、ローカルホスト コロン 3000 とは何かを説明します。
ローカルホストというのは、このパソコン自身、という意味です。
コロンのあとの3000は、3000番の窓口、という意味です。
つまり、自分のパソコンの中で動いているサーバーの、3000番窓口、ということです。
インターネットには一切出ていません。この時点では、他の人からは見えません。

止め方は、ターミナルでコントロールとCです。
ただし、開発中はずっと起動しっぱなしにします。

補足をひとつ。
npm run dev を動かしたまま、別のターミナルのタブで他のコマンドを打つのが普通です。
1つのターミナルで全部やろうとして、止めて、打って、また起動して、を繰り返すと疲れます。

確認ができたら、練習用に作ったフォルダは消して構いません。

## この章のまとめ

VS Code、Node.js、npm、Gitが揃えば、開発は始められます。

npmは部品の取り寄せ係です。部品の一覧はpackage.jsonに、実体はnode_modulesに入ります。

.env.local と node_modules は、絶対にGitに入れません。

詰まったときは、今いるフォルダと、ブラウザのコンソール。この2つを確認します。

npm run dev を動かして、ローカルホストの3000番を開く。これが開発中の基本形です。
