# 音声版 9章 ステップ1 プロジェクトを作る

ここからパート3、ハンズオンに入ります。

この章から17章までは、実際にコードを打ち込んでいく章です。
音声版では、どのファイルに、どういう役割のものを、なぜ書くのかを説明します。
コードそのものは読み上げませんので、
実際に作るときは、本編のテキストを開きながら進めてください。

逆に言うと、この音声を先に聴いておけば、
本編で写経するとき、自分が何をやっているのかが分かる状態で進められます。

この章のゴールは、空のNext.jsプロジェクトを作り、
中の不要なものを片付けて、自分のアプリの土台にすることです。

## 作る順番を、もう一度確認する

これから9つのステップで作ります。この順番には理由があります。

ステップ1、プロジェクト作成。これは土台です。

ステップ5、Claude APIに差し替え。
通信が動いている前提なので、AIのことだけに集中できます。

ステップ6、データベースに保存。

ステップ7、お気に入り一覧。

ステップ8、残りの機能。WANT機能をまとめてやります。

これは最後です。早く着手すると、構造の変更で無駄になります。

ステップ5から始めることです。

## プロジェクトを作る

作業したいフォルダに移動して、
npx create-next-app、という命令を実行します。

npxというのは、そのパッケージを、インストールせずに1回だけ実行するコマンドです。

実行すると、7つの質問をされます。回答と、その理由を説明します。

TypeScriptを使うか。イエス。5章のとおり、初心者ほど型の恩恵が大きいからです。

ESLintを使うか。イエス。書き方のミスを自動で指摘してくれるからです。

Tailwind CSSを使うか。ノー。
CSSを学ぶのが目的なので、素のCSSで書くからです。

srcディレクトリを使うか。ノー。階層が1つ増えるだけで、今回は不要だからです。

App Routerを使うか。イエス。7章で学んだ新しい方式です。必須です。

Turbopackを使うか。ノー。
速いのですが、まだ挙動が変わることがあるので、安定を重視します。

インポートのエイリアスをカスタマイズするか。ノー。
デフォルトの、アットマーク・スラッシュ、をそのまま使います。

Tailwind CSSについて、補足します。
これは実務ではよく使われます。
ですが、CSSを知らないままTailwindを使うと、何も理解できずに終わります。
まず素のCSSで作り、必要になったら乗り換えるのが健全です。

プロジェクトができたら、そのフォルダに入って、npm run dev で起動します。
ローカルホストの3000番で、Next.jsの初期画面が出れば成功です。

## できたファイルを理解する

作られたものを見ていきます。

appフォルダの中には、4つあります。
ファビコン、つまりタブのアイコン。
グローバルCSS、これは全体のCSSです。
レイアウトのファイル、これは全ページ共通の枠です。
そしてページのファイル、これがトップページになります。

appの外には、publicフォルダ。画像などの置き場です。
node_modulesフォルダ。部品の実体です。触りませんし、Gitにも入れません。
gitignoreファイル。
next.configファイル。Next.jsの設定です。今回は空のままです。
package.json。使う部品の一覧です。
package-lock.json。部品の正確なバージョンの記録です。
tsconfig.json。TypeScriptの設定です。
そしてREADMEです。

### package.jsonを見る

このファイルには、スクリプトという項目があります。
ここに書いた名前が、npm run なんとか、で実行できるコマンドになります。

devは、開発サーバーの起動。
buildは、公開用に固めること。
startは、固めたものを動かすこと。
lintは、コードの書き方チェックです。

そして、ディペンデンシーズという項目には、アプリが動くのに必要な部品が、
デブ・ディペンデンシーズという項目には、
開発中だけ必要な部品、たとえばTypeScriptなどが並びます。

### tsconfig.jsonの重要な2行

1つめが、strict、ストリクト。これをtrueにします。
型チェックを厳しくする設定です。必ずtrueのままにしてください。
緩めると、TypeScriptを使う意味が半減します。

2つめが、paths、パス。
4章で出てきた、アットマーク・スラッシュの設定です。
アットマーク・スラッシュ・lib・スラッシュ・types、と書いたときに、
プロジェクト直下のlibフォルダのtypesを指すようにしています。

### gitignoreを確認する

中に、node_modules と、.env で始まるものが書かれていることを、目で確認してください。
無ければ追記します。

2章で説明したとおり、ここは事故ると取り返しがつきません。

## 初期ファイルを片付ける

create-next-appが作るサンプルは、自分のアプリには不要です。消します。4つやります。

1つめ。トップページのファイルを、空にします。
元の中身は全部消して、
マイレシピという見出しと、アプリの説明文だけの、シンプルな内容に置き換えます。

2つめ。グローバルCSSを、空にします。
元のファイルには、大量のサンプルCSSが入っています。全部消します。
そして、最低限だけ書きます。デザインはステップ9でやるので、今は土台だけです。

書く内容は、
全要素にボックスサイジングのボーダーボックスを適用すること。
htmlとbodyのマージンとパディングをゼロにすること。
bodyに、日本語のフォントと、行の高さを指定すること。
リンクの色を継承にして、下線を消すこと。
ボタンのフォントを継承にして、カーソルをポインターにすること。
これだけです。

ここで、ボックスサイジングのボーダーボックスについて説明します。
これは、最初に必ず書く1行です。

これが無いと、幅を100ピクセルに指定した要素に、
パディングを10ピクセル足したとき、実際の幅が120ピクセルになります。
直感に反します。
この1行を書いておくと、パディングを足しても、全体は100ピクセルのまま収まります。

3つめ。レイアウトのファイルを整えます。ここで書くことは6つあります。

グローバルCSSのインポート。ここで読み込むと、全ページに適用されます。

Googleフォント、Noto Sans JPの読み込み。
これは、Next.jsが自動でダウンロードして同梱してくれる仕組みです。表示が速くなります。
このとき、variableという設定でCSS変数としてフォントを使えるようにし、
displayにswapを指定して、フォント読み込み中も文字が表示されるようにします。
これが無いと、読み込み中、画面が真っ白になります。

metadataの設定。
ブラウザのタブに出るタイトルと、検索結果に出る説明を書きます。

htmlタグのlang属性に、ja、つまり日本語を指定します。
こうすると、読み上げソフトや翻訳が正しく働きます。

そして、bodyの中にchildrenを置きます。ここに各ページの中身が入ります。

あわせて、グローバルCSSのbodyのフォント指定を、
さっきのCSS変数を使う形に変えます。
カンマ区切りで複数書くのは、上から順に、使えるものを使う、という意味です。
Noto Sansが読めなければヒラギノ、それも無ければ游ゴシック、と下がっていきます。

4つめ。publicフォルダの中のサンプル画像は、消して構いません。

## 型定義を先に書く

設計で決めたデータの形を、最初にコードにします。
これがあると、以降のコードで補完が効いて、書くのが一気に楽になります。

libフォルダの中に、types、というファイルを作って、4つのものを定義します。

1つめ、GENRES。ジャンルの一覧の配列です。
和食、洋食、中華、イタリアン、韓国料理、お弁当、こだわりなし。この7つです。
最後に as const を付けて、この7つで固定、と宣言します。

2つめ、Genre型。この配列から自動で作られる型です。
増やすときは、配列に1行足すだけで済みます。

3つめ、Recipe型。AIが返すレシピの形です。
タイトル、調理時間、人数が文字列。材料と手順が、文字列の配列です。

4つめ、FavoriteRecipe型。データベースに保存されている形です。
こちらは、材料と手順が、配列ではなく、ただの文字列です。

この、RecipeとFavoriteRecipeで材料の型が違うことが、この設計の要です。

AIと画面では、扱いやすい配列。
データベースには、単純に改行区切りの文字列。

境界で形が変わるわけです。
その変換をする場所、つまりジョインとスプリットを、意識してください。

そして、命名の違いも意図的です。

Recipe型では、調理時間を、cookingTime、というキャメルケースで書きます。
これはJavaScriptとTypeScriptの慣習です。

一方、FavoriteRecipe型では、cooking_time、というスネークケース、
つまりアンダーバー区切りで書きます。
これはデータベースの慣習です。

FavoriteRecipeは、データベースから返ってくるものを、そのまま表しています。
だから、データベースの列名に合わせています。
変換して揃えることもできますが、
データベースの形をそのまま持ってきている、と一目で分かるほうが、今回は分かりやすいのです。

git init で履歴管理を始め、git add ドットで全部を対象にし、
Next.jsプロジェクトの初期セットアップ、といったメッセージでコミットします。

このとき、git status で、node_modules が出てこないことを確認してください。
出てくるなら、gitignoreが効いていません。

そして、キリのいいところで毎回コミットしてください。
この教材では、各ステップの終わりにコミットする前提で進めます。

動いていたところまで戻れる、という安心感が、挑戦する勇気になります。
