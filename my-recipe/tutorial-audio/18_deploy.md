# 音声版 18章 デプロイ インターネットに公開する

ここからパート4、世に出す、に入ります。

この章のゴールは、手元でしか動かないアプリを、
スマホから使えるURLにすることです。

## いま何が起きているか

今の状態は、ローカルホストの3000番。自分のパソコンの中だけです。
パソコンを閉じたら、終わりです。

これからやるのは、ドット・バーセル・アップ、で終わる公開URLにすることです。
誰でも、いつでも、アクセスできるようになります。

Vercelは、GitHubにプッシュするだけで、自動的に公開してくれるサービスです。

流れはこうです。
自分のパソコンからGitHubにプッシュする。
Vercelがそれを自動で検知する。
Vercelがビルドする。
そして公開される。

一度繋いでしまえば、以降は、git push だけで更新されます。

## 準備 最終チェック

3つやります。

### 1つめ .env.local がGitに入っていないか

git status で現在の状態を確認します。
そして、git log で、.env.local というファイルの履歴を検索します。

2つ目のコマンドで、何も出なければOKです。
何か出たら、過去のコミットに含まれてしまっています。

その場合、履歴から消すのは面倒です。
一番早くて確実な対処は、
AnthropicやSupabaseのコンソールで、キーを無効化して作り直すことです。

公開してしまったキーは、もう使わない。これが鉄則です。

### 2つめ ビルドが通るか

npm run build を実行します。
ここでエラーが出るなら、デプロイしても必ず失敗します。先に直します。

### 3つめ READMEを書く

公開するなら、最低限これだけは書いておきます。

アプリが何をするものか、という説明。
構成。使っている技術の一覧です。
必要な環境変数の一覧。
セットアップの手順。
そして、注意事項です。

注意事項には、ログイン機能が無いため、
URLとSupabaseのanonキーを知っている人は誰でも、
お気に入りを閲覧、削除できること。
気になる場合は、Vercelのパスワード保護を有効にすること。
そして、Claude APIは従量課金であり、1回あたり1円未満が目安であること。
これらを書きます。

READMEは、半年後の自分への手紙です。

環境変数は何が要るか、データベースはどう作るか。
これを書いておかないと、別のパソコンで動かすとき、必ず詰まります。

## GitHubに上げる

手順は4つです。

GitHubで、ニュー・リポジトリを選びます。
リポジトリ名を入力します。
パブリックか、プライベートかを選びます。
プライベートでも、Vercelからは使えます。迷ったらプライベートです。
そして、クリエイト・リポジトリを押します。

ここで注意です。
README、gitignore、ライセンスの自動生成には、チェックを入れないでください。
既にローカルにあるので、後で衝突します。

作成後に表示されるコマンドを実行します。
リモートの追加、ブランチ名をmainに変更、そしてプッシュです。

GitHubのページを更新して、ファイルが上がっているか確認します。

そして、.env.local が無いこと、node_modules が無いことを、目で確認してください。

## Vercelでデプロイする

### アカウント作成

Vercelのサイトで、GitHubアカウントでログインします。

ここでひとつ、実際にハマった話があります。
Vercelでプロジェクトを作るには、チームが必要です。

個人アカウント単体では、作成できないことがあります。
無料の、Hobbyプランでチームを作れるので、案内に従って作成してください。
Proプランを勧められても、選ぶ必要はありません。

### プロジェクトをインポート

アド・ニュー、からプロジェクトを選び、
さきほど作ったGitHubリポジトリを選んで、インポートします。

### 設定

フレームワーク・プリセットは、Next.js。自動検出されるはずです。
ルート・ディレクトリは、リポジトリの直下にアプリがあるなら、空のままです。
ビルドコマンドと、出力ディレクトリは、既定のままです。

ルート・ディレクトリには注意が必要です。

もし、ワークスペースのリポジトリの中の、サブフォルダにアプリがある場合は、
ここにそのフォルダ名を指定します。
指定しないと、package.jsonが見つかりません、というエラーで失敗します。

### 環境変数を登録する ここが最重要

エンバイロメント・バリアブルズ、という項目を開き、3つすべてを登録します。

SupabaseのプロジェクトURL。
Supabaseのanonキー。
そして、AnthropicのAPIキーです。

ここが、初心者が最も詰まるポイントです。

.env.local はGitに含まれていないので、Vercelには届いていません。
ここで手で登録しないと、
デプロイは成功するのに、動かしたらエラーになります。

変数名のコピペミスにも注意してください。
ANTHROPIC の綴りを1文字間違えると、
SDKが見つけられず、認証エラーになります。
目で1文字ずつ確認する価値があります。

### デプロイ

デプロイを押して、2分から3分待ちます。
成功すると、紙吹雪が舞って、URLが表示されます。

## どのURLで動作確認するか

ここは必ず聞いてください。Vercelは、複数のURLを発行します。

1つめが、本番ドメイン。
プロジェクト名のあとに短い文字列が付いた形です。こちらを使います。

2つめが、デプロイ固有URL。
プロジェクト名のあとに、長いハッシュと、チーム名が付いた形です。
これは使えません。

デプロイ固有URLには、
Vercelのログイン保護、SSO保護が既定でかかっており、他人からは見えません。

これを知らずに友人に送って、開けない、と言われる、というのが定番の事故です。

プロジェクトのダッシュボードに表示される、短いほうのURLを使ってください。

## 動作確認

スマホから本番URLを開いて、ひと通り試します。

レシピが生成されること。これでClaude APIの環境変数が効いていると分かります。
お気に入り登録できること。これでSupabaseの環境変数が効いていると分かります。
一覧に表示されること。データベースから読めています。
削除できること。
そして、スマホで横スクロールが出ないこと。

### 動かないときの確認場所

レシピ生成だけ失敗するなら、
Vercelのプロジェクトの、Logs、ログの画面で、ランタイムログを見ます。

お気に入り登録だけ失敗するなら、
Supabaseの環境変数と、RLSのポリシーを確認します。

ページ自体が出ないなら、
Vercelのデプロイメンツから、該当するデプロイのビルドログを見ます。

覚えておいてください。
Vercelのログが、本番でのコンソール出力の出先です。
ローカルのターミナルに相当します。
ここを見る癖をつけてください。

## 以降の更新のしかた

git add、git commit、git push。これだけです。
Vercelが自動で検知し、ビルドして、差し替えます。

### ブランチを使った安全な進め方

git checkout ハイフンb で、作業用の枝を作ります。
そこで編集して、コミットして、その枝をプッシュします。

すると、Vercelがプレビュー環境を自動で作ります。
本番を壊さずに、実際の環境で試せます。

問題なければ、GitHubでプルリクエストを作り、
mainブランチにマージすると、本番に反映されます。

個人開発でも、この流れを使う価値があります。
壊れたけど本番は無事、という状態を作れるからです。

## 公開したあとに考えること

3つあります。

### アクセス制限をかけるか

ログイン機能が無いので、URLを知る人は誰でも操作できます。

気になる場合は、
Vercelのプロジェクト設定から、デプロイメント・プロテクション、
パスワード・プロテクション、で、サイト全体にパスワードをかけられます。

### コストの監視

Anthropicは、コンソールのUsageで使用量を確認します。予算アラートは設定済みのはずです。

Supabaseは、無料プランだと、1週間アクセスが無いと自動で一時停止します。
手動で再開できますし、データは消えません。

Vercelは、Hobbyプランの範囲なら無料です。

### 短時間の大量アクセスに注意

これは実際に起きた話です。

自動テストなどで短時間に連続アクセスすると、
Vercel、特にHobbyプランの、自動レート制限や異常検知が誤作動して、
一時的に、ほぼ全リクエストが403になることがあります。

対策は3つです。
操作の間に、2秒から4秒空けること。
失敗しても、すぐに再試行しないこと。30秒から60秒空けます。
そして、連続リトライは状況を悪化させます。
悪化したら、回復を待つしかありません。

次の章の試験で、実際にこの点を扱います。

ここまでは、言われたとおりに登録すれば動く、という書き方をしました。

設定画面の各項目は、何のためにあるのか。

登録しただけで中身が分かっていない、という状態が気持ち悪い人は、
この章を終えたら、23章を聴いてください。

Webフック、ビルド、エッジ配信、環境変数の反映タイミング。
ここで、よく分からないまま押した、ことの意味が、全部つながります。

## この章のまとめ

公開前に、git status でキーが入っていないか、
そして、ビルドが通るかを確認します。

GitHubにプッシュして、Vercelがインポートします。

環境変数は、Vercelの画面で手動登録します。.env.local は届きません。

動作確認は、短い本番ドメインで行います。デプロイ固有URLは保護されています。

以降は、git push するだけで更新されます。

本番のログは、Vercelのダッシュボードで見ます。

短時間の連続アクセスは、レート制限を誘発します。
