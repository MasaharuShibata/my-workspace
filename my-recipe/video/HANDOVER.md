## 2. 次にやること — アプリの実機デモを差し込む

### ユーザーの依頼(原文の要点)

> 実際に開発したアプリをデモで動かしているところも動画に入れてほしい。
> その方が視聴者はイメージが湧く。動かしている時に解説も入れてほしい。

### 決めた方針(着手直後に中断)

**本番アプリには触らず、アプリのコピーを手元で起動して撮る。**

理由:
- 本番を叩くとユーザーの Claude API 課金が発生し、本番DBにテストデータが入る
- Vercelのレート制限/異常検知(403)を誘発する危険がある(`CLAUDE.md`に既知の事故として記載)
- 手元なら毎回同じ結果が出せるので、撮り直しが楽

**コードは本物のまま、外部サービスだけ差し替える。**
`lib/claude.ts` と `lib/supabase/server.ts` をスタブに置き換える。
画面・CSS・操作は実物と完全に同じなので「実際のアプリ」と言って差し支えない。

### 手順(途中まで実施済み、コンテナ破棄で消えている)

1. アプリ一式をスクラッチパッドへコピー(リポジトリは汚さない)
   ```
   cp -r app components lib supabase package.json tsconfig.json \
         next.config.mjs next-env.d.ts <scratchpad>/demoapp/
   ```
2. `lib/claude.ts` の `generateRecipe()` を、**2秒ほど待ってから**決め打ちの
   レシピを返すスタブに差し替える
   → 「考案中...」の状態を映すために、待ち時間はあえて入れる
3. `lib/supabase/server.ts` を、メモリ上の配列で動く偽クライアントに差し替える
   - 使われているのは `.from().insert()` / `.from().select().order().eq()` /
     `.from().delete().eq()` の3系統。クエリビルダは `await` できる必要がある
4. `npm install` → `npm run dev`
5. Playwright でUIを操作しつつ録画(`recordVideo`)
6. 録画をコマに分解し、ブラウザ風の枠に合成して、スライドのコマとして扱う

### 実装が必要なもの

`scripts/build.py` に **`kind: demo`** を足す。
既存の `kind: anim` が「1枚のHTMLを `frames` 枚のコマとして撮り、尺に合わせて
等間隔で流す」仕組みなので、**コマの出どころを外部PNG列に変えるだけ**で載る。

```yaml
- kind: demo
  frames_dir: "demo/generate"   # 事前に用意したPNG列
  heading: "実際に動かすと、こうなります"
  narration: |
    食材を入力して、ボタンを押します。……
```

`main()` の「2) コマ割りを決めて、まとめて描画」で、
`frames_dir` があるスライドはHTML描画を飛ばし、そのディレクトリのPNGを
`segments` に積む。タイミングは `step_times(..., even=True)` を流用する。

### 撮るべき場面(案)

| 場面 | 入れたい解説 |
|---|---|
| 食材を入力 → ボタンを押す | 「ここでブラウザが入力チェックをしている」 |
| 「考案中...」の数秒 | 「いまサーバーがAIに問い合わせている。キーはここで使われる」 |
| レシピが出る | 「返ってきたJSONを画面に描いている」 |
| お気に入り登録 | 「データベースに1行追加された」 |
| 一覧ページで開閉 | 「ここではAIを呼んでいない。倉庫から出しているだけ」 |

動画のどこに差し込むかは、**「通しで見る」の直前**が自然。
先に実物を見せてから、裏で何が起きているかを追いかける流れになる。

## 3. 触るときの注意(実際に踏んだもの)

`CLAUDE.md` にも書いてあるが、特に効くもの:

- **`edge-tts` はプロキシのCA証明書を読まない**。`certifi` のバンドルに
  `/root/.ccr/ca-bundle.crt` を **追記**すれば通る。環境変数では効かない
- **Playwright同梱のffmpegは使えない**(VP8のみ・音声非対応)。
  `npm install ffmpeg-static` で別途用意する
- **日本語の音声は `WordBoundary` を返さない**。`SentenceBoundary` を使う
- **バックグラウンドで長いエンコードを走らせると、途中で切られることがある**。
  一度 `moov atom not found` の壊れたMP4ができた。完了ログ(「完成」)を
  確認してから次へ進むこと
- 音声合成はキャッシュされる(`out/<章>/s###.cues.json`)。台本の文言を
  変えていないスライドは再合成されないので、作り直しは速い

## 4. 未決の論点

- **新しい構成(PR #31)へのユーザー評価** — 声・テンポ・尺・情報量について
  まだ感想をもらえていない。デモを足す前に確認したほうが手戻りが少ない
- **2章以降の量産** — 「お願いするまで作成しなくてよい」と明言されている。
  こちらから進めないこと
- **公開時のTTS** — YouTubeで公開するなら `edge-tts` は不適。
  正規サービス(Azure Speech等)への差し替えが必要。`synth()` だけ直せば済む
