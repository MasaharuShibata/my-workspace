## 2. 第1章で決まった作り

ユーザーからの指摘はこうだった。

> アニメーションを使っている点は高く評価する。しかしキャッチーな表現を使ってはいるが、
> そもそも動画の趣旨を伝えられておらず、よく分からないものになっている。
> 第一章はまず全章の導入部分。まずシステムのデモを流して、これから全26章に渡って
> このシステムを作るチュートリアルをする旨を伝えてほしい。その上で章立てを説明し、
> 要約1章の内容に入る。

つまり **1章の解説をする前に、この教材が何なのかを伝えていなかった** のが問題だった。
そこで第1章は、章の中身に入る前に ①何を作るのか(実機デモ)②全26章でそれを作ること
③章立てと進め方、をこの順で済ませる構成にした。

以前の版にあった「朝起きたら請求69万円」は、冒頭のフックから
**APIキーの節の中の具体例**へ移した。掴みではなく、理由の説明として使っている。

この方針は `CLAUDE.md`「台本の構成」に一般化して書いてある。2章以降もそれに従う。

## 3. 2章以降の進め方

**1章につき1セッション。** 始め方と各章に使うデモシーンは `PROGRESS.md` にある。

| もの | 役割 |
|---|---|
| `PROGRESS.md` | 進捗表とセッションの始め方。**セッション間で共有できる唯一の状態** |
| `demoapp/setup.sh` | 撮影用アプリを組み立てて起動する |
| `demoapp/stubs/` | 差し替えるスタブ(Claude API / Supabase / next.config) |
| `scripts/capture-demo.mjs` | 撮影。`--scenes` で章ごとに必要なシーンだけ撮る |

撮影用アプリは**スクラッチパッドに作られるので、コンテナが破棄されると消える**。
毎回 `setup.sh` を流し直せばよい。手で組み直す必要はもう無い。

### 毎時のRoutineで自動化しようとして、やめた経緯

2026-09-20、毎時発火のRoutineで1ステップずつ進める案を試したが、初回で失敗した。
原因は**指示に作業ブランチ名とPR番号を焼き込んだこと**。土台のPRがマージされて
ブランチが自動削除された1分後に発火し、存在しないブランチを見に行った。

もう一点、この環境から作ったRoutineには**コネクタ(MCPツール)が付かない**。
発火セッションでは `mcp__github__*` が使えず、PRを作れない。
自動化を再検討するなら、claude.ai の Routines 画面から作る必要がある。

いまは自動化せず、章ごとに対話セッションで進める方針。

## 4. 触るときの注意(実際に踏んだもの)

`CLAUDE.md` にも書いてあるが、特に効くもの。

- **`edge-tts` はプロキシのCA証明書を読まない**。`certifi` のバンドルに
  `/root/.ccr/ca-bundle.crt` を **追記**すれば通る。手順は `README.md`
  「プロキシ環境での音声合成」にそのまま流せる形で置いてある。
  ⚠️ 「もう入っているか」を雑に判定しないこと。あのファイルは
  **システムのルート証明書一式 + プロキシのCA** という構成なので、
  先頭の証明書だけ見ると必ず「入っている」と誤判定する
- **Playwright同梱のffmpegは使えない**(VP8のみ・音声非対応)。
  `npm install` で入る `ffmpeg-static` を使う
- **日本語の音声は `WordBoundary` を返さない**。`SentenceBoundary` を使う
- **デモの拡大に `transform: scale()` を使わない**。Playwrightのクリック位置計算がずれて
  `<main> intercepts pointer events` で操作不能になる。アプリ文書側の `zoom` を使う
- **`pkill -f "next dev"` のような雑なプロセス停止をしない**。自分のシェルまで巻き添えで
  落ちる。ポートから引くこと(`ss -lptn 'sport = :3000'`)
- **`capture-demo.mjs` は `CHROME_PATH` を渡さないと落ちることがある**。playwright-core が
  探しに行く既定のパス(`chromium_headless_shell-<版>`)と、環境に入っている Chromium の
  版が一致しないため。`/opt/pw-browsers/chromium-*/chrome-linux/chrome` を指定する
- **バックグラウンドで長いエンコードを走らせると、途中で切られることがある**。
  完了ログ(「完成」)を確認してから次へ進むこと
- 音声合成はキャッシュされる(`out/<章>/s###.cues.json`)が、`out/` はGit管理外なので
  **セッションが変わると全スライド合成し直し**になる

## 5. 未決の論点

- **尺** — 第1章は13分15秒。長いと言われる可能性がある。削るなら
  Part 5・6 の説明か、ステータスコードの表あたりが候補
- **動画の受け取り** — mp4はGit管理外なので、生成したセッションのチャットにしか残らない。
  ステップB(動画生成)を始める前に、何章ずつ進めるかを人に確認すること
- **公開時のTTS** — YouTubeで公開するなら `edge-tts` は不適。
  正規サービス(Azure Speech等)への差し替えが必要。`synth()` だけ直せば済む
