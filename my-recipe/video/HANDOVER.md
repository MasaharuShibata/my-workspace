### このブランチでやったこと

1章を **「全26章の入口」** として作り直した。13分15秒 / 43スライド / 794コマ。

ユーザーからの指摘はこうだった。

> アニメーションを使っている点は高く評価する。しかしキャッチーな表現を使ってはいるが、
> そもそも動画の趣旨を伝えられておらず、よく分からないものになっている。
> 第一章はまず全章の導入部分。まずシステムのデモを流して、これから全26章に渡って
> このシステムを作るチュートリアルをする旨を伝えてほしい。その上で章立てを説明し、
> 要約1章の内容に入る。

つまり **1章の解説をする前に、この教材が何なのかを伝えていなかった** のが問題だった。
そこで構成をこの順に組み直した。

| | 内容 |
|---|---|
| 0:00 | 「これから作るものを、先に見せます」 → **実機デモ** 5シーン |
| 1:40 | 「これをゼロから作ります」 → **全26章**であることの宣言、対象読者 |
| 2:40 | **章立て**(Part 0〜6)、作る順番の方針(外側から内側へ / 偽物で通してから本物に) |
| 4:40 | ここから第1章の本題。3つの問いに答える形 |
| 11:00 | **冒頭のデモを裏側から説明し直して回収**、まとめ、次回予告 |

以前の版にあった「朝起きたら請求69万円」は、冒頭のフックから
**APIキーの節の中の具体例**へ移した。掴みではなく、理由の説明として使っている。

## 2. デモの撮り直しが必要になったら

撮影用アプリは **スクラッチパッドに置いたコピー** で、コンテナが破棄されると消える。
作り直す手順は次のとおり。

1. アプリ一式を作業用ディレクトリへコピーする
   ```
   cp -r app components lib supabase package.json tsconfig.json \
         next.config.mjs next-env.d.ts <作業用>/demoapp/
   ```
2. `lib/claude.ts` を、**3秒ほど待ってから**決め打ちのレシピを返すスタブに差し替える
   → 「考案中...」を映すために、待ち時間はあえて入れる。2種類返せるようにしておくと
   「別のレシピを提案してもらう」も撮れる
3. `lib/supabase/server.ts` を、メモリ上の配列で動く偽クライアントに差し替える
   - 使われているのは `.from().insert()` / `.from().select().order().eq()` /
     `.from().delete().eq()` の3系統。クエリビルダは `await` できる必要がある
   - 最初から2件ほど入れておくと、一覧が空にならず絵になる
4. `package.json` から `@anthropic-ai/sdk` / `@supabase/supabase-js` / `zod` を外す
   (スタブにしたので要らない。入れたままだとインストールが無駄に重い)
5. `next.config.mjs` に `devIndicators: false` を足す
   → これを忘れると、画面の左下に開発中バッジが写り込む
6. `npm install` → `npm run dev`
7. `node scripts/capture-demo.mjs out/demo http://localhost:3000`

**本番アプリは絶対に撮らないこと。** Claude APIの課金が発生し、本番DBが汚れ、
Vercelのレート制限を誘発する(`CLAUDE.md` に既知の事故として記載がある)。

## 3. 触るときの注意(実際に踏んだもの)

`CLAUDE.md` にも書いてあるが、特に効くもの。

- **`edge-tts` はプロキシのCA証明書を読まない**。`certifi` のバンドルに
  `/root/.ccr/ca-bundle.crt` を **追記**すれば通る。環境変数では効かない。
  ⚠️ このとき「もう入っているか」を雑に判定しないこと。`/root/.ccr/ca-bundle.crt` は
  **システムのルート証明書一式 + プロキシのCA** という構成なので、
  先頭の証明書だけ見て判定すると必ず「入っている」と誤判定する。
  証明書ブロック単位で比較して、無いものだけ追記すること(実測で30件が不足していた)
- **Playwright同梱のffmpegは使えない**(VP8のみ・音声非対応)。
  `npm install ffmpeg-static` で別途用意する
- **日本語の音声は `WordBoundary` を返さない**。`SentenceBoundary` を使う
- **デモの拡大に `transform: scale()` を使わない**。Playwrightのクリック位置計算がずれて
  `<main> intercepts pointer events` で操作不能になる。アプリ文書側の `zoom` を使う
- **バックグラウンドで長いエンコードを走らせると、途中で切られることがある**。
  完了ログ(「完成」)を確認してから次へ進むこと
- 音声合成はキャッシュされる(`out/<章>/s###.cues.json`)。台本の文言を
  変えていないスライドは再合成されないので、作り直しは速い
